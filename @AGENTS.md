# AGENTS.md

## Overview

This repository utilizes a multi-agent structure to handle development, automation, and code maintenance workflows. This document outlines the defined agents, their designated responsibilities, operational boundaries, and collaboration guidelines.

---

## Agent Roster

### 1. Architect Agent (`agent-architect`)
* **Role**: System Design & Technical Requirements
* **Responsibilities**:
  * Analyze user specifications and technical requirements.
  * Define system architecture, API schemas, and data flow models.
  * Maintain technology stack standards and project conventions.
* **Output**: Design specifications (`.md`), API contracts, database schema proposals.

### 2. Developer Agent (`agent-developer`)
* **Role**: Code Implementation & Feature Delivery
* **Responsibilities**:
  * Implement features and bug fixes according to design specifications.
  * Write clean, maintainable, and well-documented code.
  * Adhere to coding standards established by the Architect Agent.
* **Output**: Source code changes, pull requests, inline documentation.

### 3. Reviewer Agent (`agent-reviewer`)
* **Role**: Code Quality, Security & Best Practices
* **Responsibilities**:
  * Perform code reviews on incoming pull requests.
  * Check for performance bottlenecks, security vulnerabilities, and code duplication.
  * Ensure adherence to standard formatting and linting rules.
* **Output**: PR comments, approval/rejection flags, refactoring suggestions.

### 4. QA & Test Agent (`agent-qa`)
* **Role**: Testing & Quality Assurance
* **Responsibilities**:
  * Generate unit, integration, and end-to-end (E2E) test cases.
  * Identify edge cases and potential failure modes.
  * Verify bug fixes against original defect reports.
* **Output**: Test scripts (`.test.js` / `.spec.ts`), test coverage reports, issue filings.

---

## Interaction Rules & Constraints

1. **Scope Precision**: Agents must strictly adhere to their assigned role. The Developer Agent should not alter architectural specs without consulting the Architect Agent.
2. **Single File Output**: Web/UI artifacts generated by agents should follow single-file execution constraints where applicable.
3. **Format Standard**: All documentation generated by agents must use clean Markdown formatting with clear headings and code blocks.
4. **Context Preservation**: Agents must read existing repository configuration files (`package.json`, `tsconfig.json`, `.eslintrc`, etc.) before making changes.
